# Ideias 1 a 9 — Plano de implementação

> Execução inline nesta sessão (pedido do usuário: "FAÇA"), bloco a bloco, com TDD nos módulos de `lib/` e verificação no navegador com `fetch` simulado. Checkboxes marcam o progresso.

**Goal:** entregar os blocos A (tom + leitura da mensagem), B (agente: puxar assunto, situações, quando mandar), C (áudio e print) e D (simulador).

**Architecture:** lógica pura em `lib/` (prompts, parsers, schemas) testada com `node --test`; rotas finas em `app/api/*` usando `runGeneration`/`guard`; componentes React chamam as rotas via `lib/api.ts`.

**Tech Stack:** Next.js 15 App Router, React 19, zod 4, node:test com `--experimental-strip-types`.

**Spec:** `docs/superpowers/specs/2026-09-22-ideias-1-a-9-design.md`

## Global Constraints

- Node ≥ 22.6; sem dependências novas.
- Imports dentro de `lib/` usam extensão `.ts` (exigência do `--experimental-strip-types`); componentes usam `@/lib/...`.
- Textos de interface em PT-BR; comentários curtos em PT-BR como o resto do código.
- Toda rota nova: senha + rate limit (`guard`), validação zod, erros de provedor normalizados.
- Antes de cada commit: `npm run typecheck && npm run lint && npm test && npm run format:check && npm run build`.

## Bloco A

### Task A1: `parseSections` + `guard` + `lib/api.ts`

**Files:** modify `lib/prompt.ts`, `lib/generation.ts`; create `lib/api.ts`; test `tests/sections.test.ts`.

- `export function parseSections<S extends string>(raw: string, headings: [S, RegExp][]): { section: S; text: string }[]` — mesmo reconhecimento de `readHeading` (marcadores `#`/`**`, numeração, acentos, `Título: texto` na mesma linha). `parseAgentOutput` passa a usá-la sem mudar o comportamento (testes de `conversa.test.ts` continuam verdes).
- `export async function guard(req: Request): Promise<{ ok: true; headers: Headers } | { ok: false; response: NextResponse }>`.
- `lib/api.ts`: `export async function postJson<T>(url: string, body: unknown, senha: string, signal?: AbortSignal): Promise<T>` (lança `Error(data.error ?? "Erro ao gerar")`).
- Testes: seções com `###`, `**Título:** texto`, numeração e acento; texto sem títulos → `[]`.

### Task A2: prompts e schemas de ajuste/análise

**Files:** create `lib/adjust.ts`; modify `lib/validation.ts`; test `tests/adjust.test.ts`.

- `TONES = ["curto","carinhoso","seco","engracado","formal"] as const`, `type Tone`, `TONE_LABELS: Record<Tone,string>`.
- `buildToneMessages(input: ToneInput)` → `{system, messages}` com `styleRules` (exportar de `prompt.ts`) + instrução do tom + `<<<RESPOSTA_ATUAL>>>` e `<<<MENSAGEM_RECEBIDA>>>`.
- `buildReadingMessages({texto, contexto})` e `parseReading(raw): Reading | null` com `Reading = {emocao, intencao, entrelinhas, cuidado}`.
- `ajusteRequestSchema` (discriminated union por `acao`) + `parseAjusteRequest`.
- Testes: prompt de tom contém a instrução do tom e o texto delimitado; `parseReading` completo, parcial e sem títulos (`null`); schema recusa tom desconhecido e texto vazio.

### Task A3: rota `/api/ajuste`

**Files:** create `app/api/ajuste/route.ts`. `runGeneration` com `parse` → schema, `build` por ação (`maxTokens` 300 tom / 400 análise), `shape` → `{texto}` (primeira variação, sem aspas) ou `Reading` (erro se `null`).

### Task A4: interface

**Files:** modify `components/ResultCard.tsx`, `components/Generator.tsx`, `components/Conversation.tsx`, `app/globals.css`; create `components/MessageReading.tsx`.

- `ResultCard`: prop `onTone?: (tone: Tone, current: string) => Promise<string>`; estado `rawOverride`; botões de tom com estado de carregamento/erro.
